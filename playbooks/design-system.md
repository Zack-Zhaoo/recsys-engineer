# 设计推荐系统或模块

涉及业务目标、持续运营或自动决策时，先读 [产品与治理](../perspective/product-and-governance.md)。

## 收集约束

确认场景、用户目标、物料规模/生命周期、反馈、流量、延迟/成本、已有系统与不可违反约束。信息不全时先给带假设的草案，并标注会改变架构的未知项。

## 产出顺序

1. 目标：产品阶段、战略规划、北极星、代理目标、护栏和生态指标。
2. 漏斗：每级输入、输出、候选预算、延迟和降级。
3. 数据：日志、样本、标签窗口、负采样和防穿越。
4. 方法：至少当前基线、渐进方案和前沿备选。
5. Serving：索引、特征、缓存、吞吐、尾延迟和资源。
6. 评估：离线回放、shadow、灰度、A/B 和长期观察。
7. 风险：闭环、安全、隐私、公平、授权、回滚和可观测性。
8. 运营：目标复审周期、异常 owner、持续校准和策略退出机制。

## 引入前沿范式的门槛

LRM、GR、LLM、Agentic 或 Auto RS 方案都要明确替换/增强哪个职责、为何传统方案不足、等成本 Baseline、额外故障面和迁移路径。优先设计可并行灰度的混合架构。对 One Model 额外检查产品需求变化后的局部调整、异常归因和快速回滚能力。

## 最终格式

用“结论 → 产品阶段与目标 → 架构 → 模块契约 → 数据/目标 → 训练/Serving → 实验 → 持续运营与治理 → 风险 → 分阶段里程碑”组织，清楚标注假设与未决问题。
