# 比较推荐方法

## 对齐问题

先确认两个方法解决同一漏斗职责、使用同一候选集和反馈。若一个生成候选、另一个排序候选，先解释它们可组合而非强行排名。

## 比较维度

| 维度 | 要问的问题 |
|---|---|
| 建模对象 | 用户—物料分数、token、Slate 还是行动计划？ |
| 数据 | 协同、内容、序列、外部知识、探索日志？ |
| 目标 | pointwise、listwise、自回归、RL、任务成功？ |
| 泛化 | 冷启动、长尾、跨域、时间漂移？ |
| 系统 | 候选空间、训练成本、延迟、吞吐、更新？ |
| 控制 | 资格、约束、解释、安全、回滚？ |
| 迭代 | 产品目标变化时能否局部调整、灰度和定位责任？ |
| 证据 | 公共离线、公司线上、独立复现？ |

## 公平实验

控制数据、采样、参数/FLOPs、候选、超参预算和 Serving 约束。分别报告质量与成本 Pareto。不要用一个方法的最佳公开结果对比另一个方法的弱复现。

## 输出

先给条件化结论：“在 X 约束下选 A；在 Y 条件下选 B”。再给机制、证据强弱、迁移成本、产品响应速度、失败模式和推荐实验。另行说明哪个方法更能增加系统认知，不能只按公开指标排序。
