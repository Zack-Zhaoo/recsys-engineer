# 主张一：Agentic Recommendation

## 核心判断

Agentic 推荐的长期价值，不是让 LLM 输出推荐文案，也不是简单用大模型替换 ranker，而是通过 Agent 推理更准确、可更新的用户画像与偏好，在产品长期定位、即时需求和用户长期体验之间做有状态决策。

## 作者关注的真实问题

- 如何融合点击、停留、跳过、购买等行为信号与对话、文本、记忆等语义信号；
- 如何使用更小、更便宜的模型提取和维护用户偏好；
- 如何压缩推理链、缓存中间状态或分层调用模型，提高高频推荐效率；
- 如何区分稳定偏好、当前意图、临时约束和平台策略；
- 如何让画像可追溯、可纠正、可过期，而不是成为不可控的自然语言总结；
- 如何根据不确定性决定直接推荐、调用工具还是向用户澄清。

## 判断 Agent 创新的方法

对每项工作拆开验证：

1. 如果换成更强的单轮基础模型，收益是否仍然存在？
2. 记忆、规划、工具路由、反思和业务规则各自贡献什么？
3. 方法是否解决了真实应用中发生的错误，而不是只在模拟任务增加步骤？
4. Agent 改变的下一步动作是什么，失败时如何降级？
5. 用户长期体验和产品定位如何进入目标，而非只写在动机中？

## 更可能的工业形态

Agent 更适合作为推荐控制与决策层：维护用户状态，选择召回/搜索/排序工具，决定是否澄清，组合候选并解释反馈。传统高吞吐模型继续承担稳定、低延迟的候选生成和打分。

```text
用户状态与上下文
  → Agent 推理与目标规划
  → 调用模块化召回/排序/知识工具
  → 约束与安全验证
  → 推荐、澄清或行动
  → 反馈写回
```

## 主要风险

基础模型能力漂移、错误画像固化、记忆污染、推理成本、工具级联错误、虚构解释、过度主动和目标越权。更强模型不能代替权限、状态和评估设计。

## 值得研究的方向

- 行为—语义双通道的偏好状态模型；
- 小模型偏好抽取与大模型按需推理；
- 用户画像的证据化、时效性与冲突消解；
- 澄清问题的价值估计；
- 长期体验、多目标和产品定位的可审计规划；
- Agent 轨迹到传统推荐模型的蒸馏；
- 真实用户环境下的过程级评估和失败恢复。

## 修正条件

如果实践证明单轮模型在相同成本下能够稳定完成状态维护、工具选择、长期目标与错误恢复，复杂 Agent 架构的必要性应下调；如果 Agent 只能在低频演示中工作，无法带来可测的长期用户价值，也应降低该方向的工业优先级。
