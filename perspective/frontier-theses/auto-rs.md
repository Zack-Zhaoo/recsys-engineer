# 主张二：Auto RS

## 核心判断

Auto RS 是围绕业务目标自动发现问题、生成假设、修改系统、发起实验、分析结果并继续优化的推荐系统。它比自动调参或 AutoML 更接近系统级 Auto Research，能同时锻炼推荐架构、数据、实验和治理认知。

## 目标闭环

```text
业务目标与护栏
  → 诊断数据和链路
  → 形成可证伪假设
  → 提议特征、模型、参数或链路改动
  → 离线验证与风险检查
  → 申请/发起受控 A/B
  → 自动归因和切片分析
  → 继续、回滚、停止或提出下一轮
```

## 与 AutoML 的区别

AutoML 通常在固定数据、目标和搜索空间内选择模型或超参。Auto RS 还要理解推荐漏斗、业务指标、数据口径、实验平台、系统约束和组织授权，能够判断“该改哪里”和“结果为何发生”。

## 分级自治

1. **观察者**：监控并解释异常，不修改系统。
2. **研究助理**：生成假设、SQL、特征和实验方案，由人执行。
3. **受控实验者**：在明确白名单、预算和流量内自动运行实验。
4. **链路优化者**：协调召回、排序、重排和资源配置的联合优化。
5. **持续进化系统**：根据长期目标自动调整研究路线，人类负责目标、边界与重大决策。

近期应优先建设前三级。没有稳定数据口径、实验平台、回滚和审计时，不应追求高自治。

## 关键研究问题

- 如何把模糊业务目标转成可执行假设与护栏；
- 如何避免自动系统把历史实验噪声当成因果规律；
- 如何在巨大的特征、模型和链路空间中分配实验预算；
- 如何积累失败实验、同事经验和系统约束，减少重复探索；
- 如何判断继续优化、停止或切换方向；
- 如何防止目标投机、数据泄漏和无授权流量调整；
- 如何评价系统产生的认知，而不只统计赢得多少 A/B。

## 工业落地顺序

先自动化诊断、实验总结和候选方案生成，再开放代码修改、离线训练和小流量实验，最后才考虑跨链路自动发布。每一级都必须有可观察中间产物、人工确认点和稳定回退路径。

## 修正条件

如果 Auto RS 只能重复表面调参，无法提出超过资深工程师常规检查的新假设，或自动实验的误判与维护成本长期高于节省的人力，就应把它收缩为辅助工具，而不是系统自治方向。
