# 作者视角

本目录保存 1.0 公共初始版的作者判断体系。它不是个人简介，也不与 `knowledge/` 中的事实材料混写：

- `knowledge/` 回答“截至 2026-08-01，公开证据说明了什么”；
- `perspective/` 回答“作者如何分配注意力、判断价值、设计实验和选择长期方向”；
- `workspace/` 保存每位使用者自己的能力、观点、思考和灵感。

## 关于作者

本层判断出自 **力力大师兄**，先后在快手、京东、百度担任算法工程师，有多年推荐系统一线实战经验。

判断都有来源，也都有边界。读之前请先校准以下两点：

- 这些判断主要形成于短视频、电商与搜索类的大流量场景。迁移到反馈密度、物料生命周期或流量规模差异较大的业务时需要重新验证，见 [作者原则第 8 条](principles.md)。
- 一线经验覆盖的是工业落地判断，不等于对每个前沿方向都有直接生产经验。`knowledge/` 中标注为论文报告或公司报告的结论，以原文口径为准，不因作者认同而升级为已验证事实。

作者观点在本 Skill 中是**一类被显式标注的证据等级**，不是行业事实。它用于解释阅读优先级和建议方向，可以被新证据修正，见 [证据规则](../knowledge/sources/evidence-policy.md)。

## 使用原则

1. 先陈述事实、证据等级和不确定性，再给作者判断。
2. 把来源与团队背景当作阅读优先级的先验，不当作结论正确性的证明。
3. 对不符合作者偏好的研究仍做公平分析；说明为何关注度较低，不用偏好代替技术论证。
4. 作者观点必须允许被新证据修正。重要判断写出边界、反例和可证伪条件。
5. 用户明确要求中立综述时，正文以公共证据为主，把作者视角单独标成“作者判断”。

## 默认输出中的作者视角

对论文分析、研究选题、前沿判断和系统方案，必要时在客观分析之后增加一个简短区块：

```text
作者判断
- 值得关注的原因：……
- 当前最大的保留意见：……
- 对工业系统真正有用的部分：……
- 最值得带走的思考：……
```

不要在每个基础概念回答中机械追加这一段；只有作者判断能实质改变结论、阅读优先级或下一步动作时才使用。
