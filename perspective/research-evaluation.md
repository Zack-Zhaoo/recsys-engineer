# 研究与工业文章评价方法

本方法用于分配阅读时间、判断结论可信度和提取研究灵感。它是一套作者偏好，不是学术质量排行榜。

## 目录

- 一、先做来源穿透
- 二、先分类，再选择评价标准
- 三、检查论证密度
- 四、把表达质量作为弱信号
- 五、分开评价可信度与启发价值
- 六、检查场景迁移性
- 七、寻找外部校验
- 输出卡片

## 一、先做来源穿透

不要停在“来自某家公司”。依次确认：

```text
公司 → 业务线 → 团队 → 作者身份 → 合作关系 → 是否拥有真实生产问题
```

### 作者的关注先验

- 对快手、阿里妈妈、字节、美团、腾讯、Meta、Google 的推荐论文和技术报告给予较高初始关注；其中快手在推荐技术上的持续前沿投入，使其材料获得更高阅读优先级。
- 对纯学术界论文通常投入较少精读时间；中国人民大学高瓴人工智能学院赵鑫、窦志成老师相关团队是明确例外。
- 同一公司内部继续区分业务线。针对复杂大流量推荐问题，抖音短视频核心推荐团队的材料通常比字节内部更垂直或规模更小的业务团队获得更高迁移置信先验。这个例子只说明场景规模与生产所有权会影响阅读优先级，不表示后者研究必然更差。
- 正式员工主导、生产责任清晰的团队材料，通常比校企合作或实习生主导的工作获得更高工业置信先验；后者仍可能有优秀方法，但需要额外确认生产参与程度、数据口径和系统约束。

来源先验只能决定“先读什么、读多深”。不得写成“名校/大厂作者所以结论必然正确”。

## 二、先分类，再选择评价标准

2023 年以前，大量推荐研究围绕 DLRM，特别是精排结构、多任务和跨场景建模，例如 PPNet、STAR 等。如今研究类型更加分散，阅读前先归入以下类型：

| 类型 | 优先检查 |
|---|---|
| 传统漏斗优化 | 是否解决真实瓶颈；是否超过强工业 Baseline；迁移成本是否低 |
| Large Ranking Model | 增益来自 Scaling、数据、结构还是算力；等成本曲线是否充分 |
| 生成式推荐 / One Model | 作者和团队背书；训练与推理成本；可控性；对产品变化的响应速度 |
| Agentic 推荐 | 增益来自基础模型变强，还是 Agent 设计、记忆、工具与业务机制 |
| Auto RS | 是否真的接入数据、实验和决策闭环；自动化边界与安全控制是否清晰 |
| LLM + 传统推荐 | LLM 改变了哪项真实能力；离线产物能否由小模型承接 |
| Semantic ID / 多模态 | 是否同时保留协同信号、增量更新与线上效率 |
| 统计启发式或旧漏斗改造 | 是否产生新的可迁移认知；否则降低阅读优先级 |

对 OneRec 一类重模型，只有强作者背书还不够，还要看其是否提供与高实践成本相匹配的系统价值。对 Agentic 工作，要特别排除“仅因为 2026 年基础模型比 2024 年更强”的能力红利。

## 三、检查论证密度

重点寻找：

- 核心主张是否由直接实验支持，而不是只用大篇幅背景和结构介绍包装；
- 消融是否能拆开数据、目标、结构、容量、训练技巧和推理策略；
- 是否跨数据集、场景、人群、物料和时间窗口验证；
- Baseline 是否足够强，调参预算、候选集、算力和延迟是否公平；
- 是否报告方差、失败场景、成本曲线和负面结果；
- 线上实验是否说明流量、周期、同期改动和护栏。

推荐会议论文篇幅有限，但如果模型结构与业务背景占据大量篇幅，关键实验和消融极薄，应降低结论置信度。漂亮且针对核心机制的多角度实验，比堆叠大量无关表格更有价值。

## 四、把表达质量作为弱信号

排版、绘图、表格对齐、术语一致性和图例完整性反映作者是否认真检查细节。花哨、混乱或不规整的表达可以触发更谨慎的复核，但不能单独证明论文错误，也不能压过严谨实验。

## 五、分开评价可信度与启发价值

不要用单一总分掩盖两种价值：

### 结论可信度

综合来源穿透、实验严谨性、复现状态、场景边界和成本披露，回答“作者的主张值得相信到什么程度”。使用 `high / medium / low / unknown`，必须给理由。

### 启发价值

回答“即使不直接相信指标，这篇工作能否改善我的问题定义、系统认知或实验设计”。重点看：

- 是否提出真实而通用的问题；
- 是否提供巧妙、可迁移的解法；
- 是否帮助理解行为信号与语义信号如何协同；
- 是否带来效率、小模型承接、系统自动进化等新视角；
- 是否能转化成低成本局部实验。

一篇低可信度论文可以具有高启发价值；一篇实验严谨的论文也可能只有低认知增量。

## 六、检查场景迁移性

至少记录：产品形态、流量量级、反馈密度、物料规模与生命周期、用户意图强度、实时性、商业目标和合规约束。使用 `high / medium / low / unknown` 表示迁移性，不把某个场景的提升数字直接换算到另一业务。

## 七、寻找外部校验

对重要或热门工作继续检查：

- 是否有独立复现、开源实现或跨公司采用；
- 知乎等技术社区是否出现有内容的质疑、复现和作者回应；
- 同一结论是否被不同来源重复观察；
- 是否能向对应公司的可信从业者求证生产背景。

私人交流只能更新个人置信度。未获授权时，不在公开 Skill 中披露朋友身份、内部信息，也不把私下判断伪装成公开事实。

## 输出卡片

```yaml
research_type: agentic-recommendation
funnel_or_system_role: user-understanding-and-control-plane

source_prior:
  level: high
  basis: 核心推荐团队正式员工主导

conclusion_confidence:
  level: medium
  basis:
    - 消融覆盖 Agent 组件
    - 缺少独立复现

inspiration_value:
  level: high
  takeaways:
    - 使用小模型承接偏好抽取
    - 行为与语义信号分层融合

scenario_transferability:
  level: medium
  gap:
    - 原场景反馈更密集
    - 未验证高 QPS 延迟

author_attention: deep-read
next_action: 进入灵感孵化，而不是直接复现完整系统
```

最终输出先给证据判断，再给作者阅读建议。不要把“作者不准备精读”写成“该研究没有价值”。
