# 推荐系统基础

## 任务本质

推荐是在有限曝光预算下，对用户、上下文、候选物品和平台目标做条件决策。观察到的点击不是完整偏好，而是“被展示后发生的行为”。

需要区分：

- 相关性：用户是否可能感兴趣；
- 价值：点击之后是否产生时长、转化或长期满意；
- 约束：库存、频控、安全、生态、公平与商业规则；
- 探索：是否为不确定但潜在高价值的内容分配曝光。

## 反馈类型

- 显式反馈：评分、喜欢、不喜欢、关注、收藏。
- 隐式反馈：曝光、点击、跳过、停留、播放完成、购买。
- 延迟反馈：复访、留存、长期转化、创作者供给变化。

隐式反馈受曝光策略、位置、界面和历史模型影响。训练集不是从真实偏好分布独立采样得到的。把隐式反馈当作“同一用户下的相对偏好”而不是绝对评分，以及用神经网络替代内积建模交互，是两条影响深远的早期路线。[SRC-BPR-2009] [SRC-NCF-2017]

## 三类问题

- 预测：估计用户对候选的响应或价值。
- 检索：在超大物料池中快速找到可能相关的候选。
- 决策：在多目标、约束和不确定性下选择最终列表。

## 常见结构性难题

- 冷启动：新用户、新物品和新场景缺乏交互。
- 长尾：训练和曝光集中于头部物品。
- 反馈闭环：模型影响曝光，曝光又塑造未来数据。
- 兴趣漂移：长期偏好与短期意图同时变化。
- 多目标冲突：点击、时长、满意、收入和生态不一致。
- 反事实缺失：无法直接知道未曝光候选的真实结果。

## 最小分析框架

讨论任何推荐问题时先回答：

1. 决策单位是物品、序列还是交互动作？
2. 候选空间有多大，延迟和吞吐预算是什么？
3. 标签如何产生，负样本来自哪里？
4. 离线指标与线上目标如何连接？
5. 模型改变曝光后，数据分布会怎样变化？
