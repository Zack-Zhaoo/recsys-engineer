# 生成式推荐（Generative Recommendation）

生成式推荐把推荐建模为 token 序列生成：模型可生成物料的 Semantic ID、候选序列或完整 Slate。它试图统一检索、排序和序列建模，但不会消除资格、安全、索引和策略约束。

## 核心部件

- **物料 Token 化**：原始 item ID、Residual Quantization 产生的 Semantic ID、文本/多模态 token。
- **生成目标**：next-item、多个未来行为、候选集合或有序 Slate。
- **解码与约束**：beam search、constrained decoding、去重、合法性校验和在线新物料更新。
- **训练信号**：行为序列、自回归目标、多任务行为类型与偏好对齐。

## 谱系与前驱

生成式召回不是凭空出现的范式。推荐侧的前身是模型与索引联合学习那条线：TDM 的逐层树遍历与 Deep Retrieval 的可学习路径，和逐 token 生成语义 ID 是同一个粗到细的结构化解码动作。差别在承载结构：前两者维护显式的树或路径矩阵，索引仍是独立于打分模型的实体；生成式把索引压进解码器参数与码本，两阶段的度量错配从根上消失，代价是更新索引变成了更新模型与码本。[SRC-TDM-2018] [SRC-DEEP-RETRIEVAL-2020] 思想源头在检索界：DSI 最早把"模型即索引"做成文档检索系统，生成式检索这个提法即来自这条线。[SRC-DSI-2022]

## 代表进展

"生成式"在这些工作里有两个含义，读时先分开。范式层指 token 化输入、Transformer 主干与 scaling，可以用在排序上，但模型仍是打分器，输出契约与传统精排相同；任务层指真的把答案解码出来，天然属于召回与列表生成。真正用生成产出排序结果的，只有列表生成一条窄线。

- TIGER 用 Semantic ID 和生成式检索连接语义泛化与协同信号，成为生成式召回基线之一。只覆盖召回，没有逐候选打分接口。[SRC-TIGER-2023]
- HSTU 探索面向大规模推荐的生成式序列架构与 Scaling，在召回与排序两级分别实例化：召回侧解码生成，排序侧是生成式架构的打分器，仍输出逐候选多任务分。[SRC-HSTU-2024]
- OneRec 报告了统一生成式推荐框架与工业实践，强调从分阶段漏斗向生成式系统演进，属于任务层的整列生成，用一个模型同时承担检索与排序。[SRC-ONEREC-2025]
- 美团的 MTGR 保留传统 DLRM 的交叉特征并做用户级压缩，是范式层在排序侧的应用，不解码生成任何物料；配套的 MTGenRec 进一步处理动态稀疏表、序列负载均衡和百卡训练，说明训练/Serving 系统不是生成式推荐的附属问题。[SRC-MTGR-2025] [SRC-MTGENREC-2025]

## 现实成熟度

截至 2026-08-28，生成式推荐已从概念验证进入多篇大规模工业论文阶段，但公开证据仍集中于少数头部平台。传统漏斗在可控性、候选资格、增量更新、调试和低延迟上仍有优势。更现实的演进往往是混合式：生成式召回/教师模型加传统排序和策略。

作者进一步认为 One Model 的工业成熟度被高估，尤其要补充验证产品需求变化后的局部调整、异常归因、灰度和回滚能力。该判断及其反证条件见 [One Model 的边界](../../perspective/frontier-theses/one-model-limits.md)。

## 关键难题

- Semantic ID 的稳定性、碰撞、层级含义与新物料增量编码。
- Token 级 likelihood 与最终用户价值、列表指标不一致。
- 自回归解码延迟、重复/非法 ID、热门偏置和 beam 搜索误差。
- 多行为序列如何表达负反馈、意图切换和长期价值。
- 如何与广告、库存、安全、配额和探索等硬约束结合。

## 研究建议

强 Baseline 至少包括同数据同容量的双塔召回、序列排序，以及等延迟级联。分别消融 tokenizer、生成目标和解码器；报告合法率、覆盖、新物料、尾部、端到端延迟及线上结果。
