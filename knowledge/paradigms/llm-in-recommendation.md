# LLM 与推荐

LLM 在推荐中的角色应明确区分，否则“用了 LLM”没有技术含义。

## 四种角色

1. **表示与特征增强**：编码标题、评论、画像或多模态描述。
2. **数据/监督增强**：生成解释、属性、难负例、偏好摘要或教师标签。
3. **直接推荐器**：把推荐任务转成提示、问答、排序或生成任务。
4. **交互与编排层**：理解自然语言意图并调用检索、排序和外部工具；进一步见 [Agentic 推荐](agentic-recommendation.md)。

## 代表工作

- P5 将多个推荐任务统一为文本到文本范式，展示了 prompt-based recommendation 的通用接口。[SRC-P5-2022]
- TALLRec 用轻量调优让 LLM 适配推荐任务，代表“通用语言能力 + 推荐适配”的路线。[SRC-TALLREC-2023]

## 优势与边界

LLM 擅长冷启动语义、开放词表、自然语言约束、解释和跨域知识；但闭源模型版本漂移、成本、延迟、ID 协同信号不足、幻觉和不可重复性会阻碍核心高 QPS 排序。

文本化 ID 并不会自动学到协同过滤。若实验仅在候选很小、文本信息强的数据集上进行，不能直接推断其可替代工业检索和排序。

## 评估清单

- 与纯协同、纯内容、融合模型比较，并控制候选集和外部知识。
- 报告 seen/unseen item、冷启动、流行度分桶与跨域迁移。
- 统计 token、延迟、吞吐、缓存命中与调用成本。
- 检查事实性、可控性、隐私泄漏、提示注入和模型版本稳定性。
- 解释是否用到了测试期间不可得的信息。
