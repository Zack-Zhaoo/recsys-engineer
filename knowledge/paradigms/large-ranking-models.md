# Large Ranking Model（LRM）

LRM 是对工业排序模型的规模化与统一化探索：扩大参数、数据、行为序列、特征交互或任务范围，并让容量增长转化为可持续的线上收益。它不是简单把通用 LLM 搬到排序。

## 2026-08 快照

- HSTU 展示了面向推荐序列的生成式、流式转导架构和大规模训练路径，是推荐模型 Scaling 的重要代表。[SRC-HSTU-2024]
- RankMixer 用多头 token mixing 与 per-token FFN 组织特征交互，报告了大规模工业推荐与广告排序实践。[SRC-RANKMIXER-2025]
- TokenMixer-Large 延续 token mixing 路线，关注超大规模排序模型中的计算和表达效率。[SRC-TOKENMIXER-LARGE-2026]
- 2026 年的 Kunlun、TRM、SIF 继续探索统一表示、序列—特征交互和可扩展排序架构；目前应视为论文公开结果，不等同于行业普遍生产化。[SRC-KUNLUN-2026] [SRC-TRM-2026] [SRC-SIF-2026]

## Scaling 维度

1. 参数与 Embedding 容量。
2. 用户历史长度、事件粒度和时间跨度。
3. 稀疏/稠密特征 token 化与高阶交互。
4. 多场景、多域、多任务和跨阶段统一。
5. 预训练、蒸馏、稀疏激活、缓存和分层 Serving。

## 与其他范式的边界

- LRM 仍通常对给定候选打分；GR 倾向直接生成物料标识或 Slate。
- LLM-in-Rec 借助语言模型的世界知识和文本推理；LRM 的 token 可以是 ID/特征，并不天然具备语言能力。
- Agentic Rec 组织记忆、规划、工具和交互流程；它可以调用 LRM，但不是 LRM 的同义词。

## 研究和落地难点

- 推荐 Scaling Law 是否跨数据、序列、参数和 Serving 约束稳定成立。
- 计算增长与增量收益是否优于更好的数据、采样和目标。
- 超长历史中的噪声、反馈闭环和概念漂移。
- 参数增大后的校准、尾延迟、热 key、容灾和迭代速度。
- 大模型教师向多级漏斗蒸馏时如何保留 top 区域与长尾发现。

## 最小验证

保持样本、目标和 Serving 条件一致，至少画出“离线质量—训练 FLOPs—推理成本—线上指标”的 Pareto 曲线。若只扩大模型而未设置等成本 Baseline，不能归因于架构。
