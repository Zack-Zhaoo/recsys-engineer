# 特征与 Embedding

## 特征分组

- 用户：长期偏好、近期序列、人口/设备信息（需合法合规）。
- 物料：ID、类目、创作者、文本、多模态内容、质量与新鲜度。
- 上下文：时间、位置、入口、网络、会话和页面状态。
- 交叉：用户—物料、query—item、场景—行为统计。

每个特征都要声明 owner、语义、时间窗口、默认值、更新频率、线上来源和退役策略。

## Embedding 设计

把共现行为序列当作语料学习物料向量，是 ID Embedding 最早的通用做法之一。[SRC-ITEM2VEC-2016]

Embedding 表常占推荐模型大部分参数和内存。[SRC-DLRM-2019]需要共同设计词表裁剪、hash 冲突、维度、频次自适应、量化、共享、初始化和增量更新。高频 key 的通信与缓存会形成尾延迟热点。

序列特征不只是 ID 列表：事件类型、时间间隔、场景、停留和负反馈决定行为语义。Semantic ID 能带来结构共享和冷启动泛化，但 tokenizer 稳定性与重编码成本必须计入。

## 特征平台契约

- Offline/online 使用同一变换定义或可验证等价实现。
- Point-in-time correct join，防止穿越。
- 特征版本、血缘、回填、TTL 与缺失告警。
- 隐私最小化、访问控制和删除传播。

## 诊断

用特征覆盖与漂移、Embedding 范数/碰撞、消融、permutation importance、分群效果和线上缺失日志联合判断。不要根据单次 feature importance 直接推断因果价值。
